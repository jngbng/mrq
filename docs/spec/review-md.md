# 스펙: `review.md` 문법

규범 문서. 관련: FR-004, FR-005

`review.md`는 사람과 AI 에이전트 **모두의** 완전한 읽기·쓰기 면이다. 면이 하나이고
문법이 하나다. 따라서 이 파서는 AI가 생성한 임의의 마크다운을 입력으로 받아도 깨지지
않아야 한다 — 표, 중첩 코드 펜스, 수평선, 앵커 문법의 인용이 모두 평범하게 들어온다.

`review.json`이 정본이므로, 파싱 실패가 상태를 통째로 날리지는 않는다.

## 2. 앵커는 헤더 **위**에 둔다

```markdown
<!-- mrq:a1b2c3d4e5f6 v:9f2e3a -->
## [ ] src/api/client.py:102 — @jdoe
```

앵커가 헤더 아래에 있으면 reply 영역의 끝을 "다음 앵커 직전"으로 정의했을 때 다음
스레드의 `## ` 헤더 줄이 reply에 끼어든다. 파서가 "끝에서 헤더처럼 보이는 줄을
떼어낸다"는 보정을 하게 되고, 그 보정은 답글이 `## `로 끝날 때 오작동한다.

앵커를 블록의 첫 줄로 두면 블록 경계와 reply 끝이 **같은 토큰 하나**로 정의된다.

앵커 id는 **항상 GitLab discussion id**다(MUST). `general` 같은 고정 문자열을 쓰면
안 된다(MUST NOT) — 파일 외 코멘트도 각자 고유한 discussion id를 가지며, 고정
문자열을 쓰면 그런 코멘트가 둘 이상인 MR에서 중복 앵커가 되어 §7에 따라 전체
파싱이 실패한다.

## 3. 헤더 형식

```
## [<상태>] <path>:<line> — @<author>  [배지...]
## [<상태>] (general) — @<author>
```

| 상태 문자 | `local.state` |
|---|---|
| 공백 | `todo` |
| `x` | `done` |
| `~` | `replied` |
| `-` | `skipped` |

`<path>:<line>` 형태가 앞에 오므로 Emacs `compilation-error-regexp-alist`가 그대로
잡는다. 정규식은 `^## \[.\] \(.+?\):\([0-9]+\)`이며 `(general)` 헤더는 매치되지
않는다 — 의도된 동작이다.

`location`이 `null`인 스레드(파일 외 코멘트, 이미지·파일 코멘트)는 `(general)`
형태를 쓰고 배지를 붙이지 않는다. 위치를 못 찾은 것이 아니라 위치가 없는 것이므로
`stale` 배지를 붙이면 안 된다(MUST NOT).

`confidence == "stale"`인 스레드의 헤더는 `<path>:1`로 쓴다. 헤더에서 점프하는 것은
사용자의 명시적 행동이므로 1행도 허용한다. 진단으로는 표시하지 않는다
(`docs/spec/reanchoring.md` 참조).

### 배지

| 배지 | 조건 | 이유 |
|---|---|---|
| `` `stale` `` | `location.confidence == "stale"` | 위치를 못 찾았음을 즉시 알려야 한다 |
| `` `fuzzy` `` | `location.confidence == "fuzzy"` | **눈으로 확인할 것이 어느 것인지** 알려준다. 없으면 전부를 의심하게 된다 |
| `` `no-reply` `` | `server.repliable == false` | 답글을 써도 전송되지 않는 곳에 시간을 쓰지 않도록 |

## 4. 코드 블록에는 `anchor.hunk`를 넣는다

현재 코드 한 줄만 보여주면 "왜 그런 지적을 했는지" 알 수 없다 — 특히 그 코드가 이미
바뀐 뒤라면 그렇다. 리뷰어가 본 diff를 그대로 보여주면 사용자가 맥락을 즉시 파악한다.

- `anchor.hunk`가 있으면 ` ```diff ` 펜스로 출력한다(SHOULD)
- 없으면 `anchor.context_before` + `anchor.line` + `anchor.context_after`를 파일
  언어 펜스로 출력한다(MUST)

## 5. 렌더링 규칙 (FR-004)

- 스레드 순서는 **`location`이 없는 스레드 먼저(그들끼리는 `notes[0].created_at`
  순), 그 다음 `(location.path, location.line)` 정렬**이어야 한다(MUST).
  안정 정렬이라 재렌더 시 diff가 최소가 된다
- 서버에서 이미 resolve된 스레드는 기본적으로 출력하지 않는다. `--all`로 포함한다
- **예외**: `server.resolved == true`여도 `local.reply`가 비어 있지 않거나
  `local.state != todo`인 스레드는 `--all` 없이도 출력해야 한다(MUST). 동료가 내
  스레드를 먼저 resolve했을 때 아직 전송하지 않은 내 답글이 사라지면 안 된다
- `### reply` 뒤에 빈 줄 하나, 본문, 다음 앵커 전에 빈 줄 하나를 고정 출력한다(MUST)
- 빈 reply는 `### reply` + 빈 줄만 출력한다
- 인용은 `> **@author** YYYY-MM-DD HH:MM` 다음 줄부터 본문. 노트 사이에 `>` 한 줄
- 노트 본문의 **모든 줄**에 `> `를 붙인다(MUST). 빈 줄은 `>` 단독으로 쓴다 —
  접두사를 빼면 인용이 끊기고, GitLab 코멘트에는 빈 줄을 포함한 코드 블록이 흔하다

## 6. 파싱 규칙 (FR-005)

```
1. 파일을 줄 단위로 훑되, fenced code block(``` 또는 ~~~) 안에서는
   앵커를 인식하지 않는다.
2. 앵커 = ^<!-- mrq:([0-9a-f]{8,}) v:([0-9a-f]{6}) -->$
   0열에서 시작하고 그 줄에 다른 내용이 없어야 한다.
3. 블록 = 앵커 줄부터 다음 앵커 줄 직전까지, 또는 EOF까지.
4. 체크박스 = 앵커 바로 다음 줄의 ^## \[(.)\]
5. reply = 블록 안 첫 ^### reply$ 다음 줄부터 블록 끝까지.
   앞뒤 빈 줄만 제거하고 내부는 바이트 그대로 보존한다.
6. reply 영역 밖의 모든 내용은 무시한다.
```

**규칙 1(fence 추적)이 필수다**(MUST). AI가 설명을 위해 앵커 문법을 코드 펜스 안에
인용하는 경우가 실제로 발생하고, 추적하지 않으면 블록이 둘로 쪼개진다.

**규칙 6이 "인용을 수정하지 마세요"를 불필요하게 만든다.** 지킬 수 없는 규칙을
요구하는 대신, 수정해도 무해하게 만든다. `review.json`이 정본이므로 md의 인용·코드
블록·사람이 끼워 넣은 메모는 모두 버려도 손실이 없다.

### 정규화

- 줄 끝은 `\n`으로 통일한다(MUST)
- reply 영역의 앞뒤 빈 줄을 제거한다(MUST)
- **내부는 바이트 보존한다**(MUST). 코드 블록 안의 공백을 건드리면 답글 내용이 망가진다

### 라운드트립 성질

```
render(parse(render(j))) == render(j)      바이트 일치 (MUST)
```

`parse(render(j)) == j`는 성립할 수 없다 — md에 없는 필드가 json에 있다. 위 성질이
올바른 형태이며, 렌더 → 파싱 → 렌더가 안정점에 도달함을 보장한다.

## 7. 에러와 경고

"부분 적용 금지"를 모든 이상에 적용하면 AI가 헤더 한 줄을 지웠을 때 작업 전체가
날아간다. 그래서 둘로 나눈다.

| 상황 | 판정 | 처리 |
|---|---|---|
| 같은 앵커 ID가 두 번 등장 | **에러** | 의도를 확정할 수 없다 |
| 체크박스 문자가 `[ x ~ -]` 밖 | **에러** | 추측하지 않는다 |
| 앵커 다음 줄이 `## [`가 아님 | 경고 | 해당 스레드 상태 유지 |
| 블록에 `### reply`가 없음 | 경고 | 해당 스레드 reply 유지 |
| `review.json`에 없는 앵커 ID | 경고 | 무시 |
| json에 있는데 md에 없음 | 조용히 통과 | 상태 유지 (`--all` 미지정 시 정상) |
| `v:` 토큰 없음 | 경고 | **편집된 것으로 간주** (보수적) |

- 에러가 **하나라도** 있으면 아무것도 쓰지 않고 **exit 2**로 끝낸다(MUST).
  줄 번호와 함께 보고해야 한다(MUST)
- 경고는 진행하되 전부 출력해야 한다(MUST)

보고 형식은 `review.md:<line>: <메시지>`여야 한다(MUST) — 에디터가 compilation
버퍼에 넣어 바로 점프할 수 있다.

## 8. 테스트

라운드트립을 property 테스트로 검증한다. hypothesis로 "AI가 쓸 법한 답글"을 생성한다.

- 마크다운 표
- 중첩 코드 펜스 (4백틱으로 감싼 3백틱)
- 수평선 `---`
- `<!-- mrq:... -->` 문법을 코드 펜스 안에 인용
- `## `로 시작하는 줄, `### reply` 문자열 자체
- CRLF, 탭, 이모지, 매우 긴 한 줄, 앞뒤 공백

§7의 에러/경고 표 전체를 케이스화한다. 에러 케이스는 **json이 수정되지 않았음을**
단언해야 한다(MUST).
