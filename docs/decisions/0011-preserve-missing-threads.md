# 0011. 응답에서 사라진 스레드를 `server.missing` 으로 보존한다

날짜: 2026-10-13 · 상태: 채택 (잔여 항목 R5 를 해소. `data-model.md` §6 의
"서버에서 사라진 스레드만 제거한다" 를 조건부로 바꾼다)

## 배경

`pull` 의 `local.*` 보존은 "직전 json 에 같은 id 가 있을 때" 로 정의되어 있다.
따라서 스레드가 한 번 응답에서 빠지면 그 스레드의 `local.state`·`local.reply`·
`pushed_hash` 가 함께 사라지고, 다시 나타나도 돌아오지 않는다.

서버에서 진짜로 삭제된 경우에는 맞는 동작이다. 문제는 **응답만으로는 삭제와
일시적 결손을 구분할 수 없다는 것**이다 — `glab --paginate` 가 페이지를 조용히
빠뜨리거나, 권한 변경으로 일부 스레드가 안 보이는 경우에도 같은 응답이 된다.
그때 사라지는 것은 전송하지 않은 답글, 즉 **이 도구에서 유일하게 복구 불가능한
데이터**다 (`data-model.md` §1 "손실 복구").

계획 2 가 끝난 시점까지 미뤄 둔 이유는 표시를 `push` 가 어떻게 다룰지가 정해지지
않았고, 스키마에 필드를 더하는 결정이 거기 묶여 있었기 때문이다.

## 결정

**`server.missing` (boolean) 을 더한다.** `pull` 은 응답에 없는 스레드 중
`local.reply` 가 비어 있지 않거나 `local.state != todo` 인 것을 제거하지 않고
`missing = true` 로 표시한다. 다시 나타나면 `false` 로 되돌린다.

`push` 는 `missing == true` 인 스레드를 전송 대상에서 제외한다. `--force` 로도
보내지 않는다.

규범 정의는 `data-model.md` §4.10 에 있다.

## 근거

**필드 없이 "그냥 보존만" 하는 안을 기각했다.** 스키마를 건드리지 않는 대신 그
스레드를 마지막 스냅샷 그대로 남겨 두는 선택이었다. 데이터 손실은 똑같이 막지만,
`push` 가 없는 discussion 에 POST 해 404 를 받고 그것을 `push_error` 로 기록한다.
`404` 의 `retryable` 은 `false` 다 — "다시 보내도 같은 결과" 라는 뜻에서는 맞지만,
결과적으로 **"다시는 전송되지 않는다" 가 사용자에게 아무 설명 없이 영구화된다.**
`status` 는 그 스레드를 여전히 전송 대상으로 세고, 매번 한 건이 조용히 실패한다.
실패를 사후에 해석하게 만드는 쪽이 필드 하나보다 비싸다.

**`--force` 를 예외로 두지 않는 이유.** `--force` 의 의미는 "서버가 pull 이후
바뀐 것을 무시한다" 다. "서버에 없다" 는 같은 종류의 판정이 아니다 — 보낼 곳이
없는 요청을 강제할 방법이 없고, 플래그가 그것을 할 수 있는 것처럼 보이면
사용자는 답글을 직접 옮기는 유일한 복구 경로를 찾지 않는다.

**미전송 작업이 없는 스레드는 그대로 제거한다.** 보존해서 표시할 로컬 상태가
없으므로, 남기면 `review.md` 와 `status` 에 설명할 수 없는 항목이 쌓인다.

**표시가 영구화되지 않게 `false` 로 되돌리는 것이 MUST 인 이유.** 일시적 결손이
가정의 절반이므로 복귀는 정상 경로다. 되돌리지 않으면 멀쩡한 스레드가 영구히
전송 대상에서 빠지고, 그것은 이 결정이 막으려던 손실과 같은 모양이다.

## 대가

- 스키마에 필드가 하나 늘었다. `additionalProperties: false` 이므로 세 구현이
  함께 알아야 하고, 키가 없는 기존 파일을 읽을 때 `false` 로 다루는 규칙이
  필요하다 (`required` 에 넣지 않은 이유다)
- `review.md`·`list`·`status` 에 배지와 경고가 하나씩 늘었다
- `pull` 의 보존 로직이 "있으면 이어받는다" 에서 "없으면 조건을 보고 남긴다" 로
  분기가 하나 늘었다. `test_pull_drops_threads_removed_on_server` 는 미전송 작업이
  없는 경우로 좁혀 유지하고, 있는 경우를 새 테스트로 추가한다
