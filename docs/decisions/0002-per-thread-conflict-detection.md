# 0002. 충돌은 스레드 단위로 보고한다

날짜: 2026-10-11 · 상태: 채택

## 배경

[0001](0001-human-and-ai-are-peers.md)에 따라 md와 CLI가 모두 `review.json`을 쓴다. 사람이 Emacs에서 답글을 쓰는
동안 AI가 `mrq reply`로 같은 json을 고칠 수 있다.

검토한 대안:

- **md 우선**: CLI 변경은 즉시 md를 재렌더하고 `sync`는 md를 무조건 덮어쓴다.
  단순하지만 사람이 버퍼를 저장하지 않은 채 들고 있으면 AI의 작업이 조용히 사라진다
- **낡은 md 거부**: json이 렌더 후 변경되었으면 `sync`가 전체를 거부한다.
  "부분 적용 금지"와 일관되지만 AI가 일할 때마다 사람 버퍼가 무효화된다

## 결정

스레드별로 비교해 **양쪽이 같은 스레드를 서로 다르게 고친 경우만** 충돌로 보고한다.
충돌이 하나라도 있으면 아무것도 쓰지 않고 exit 3으로 끝낸다.

판정에는 `rendered_at`, `local.touched_at`/`touched_by`, 그리고 `review.md`의 앵커
주석에 적힌 렌더 시점 상태 해시(`v:`)를 쓴다.

## 결과

- `v:` 해시가 없으면 거짓 충돌이 발생한다 — AI가 스레드 1을 고친 직후 사람이 스레드
  7만 저장했을 때 `touched_at > rendered_at`만으로는 구분이 불가능하다
- 해시 충돌은 "사람이 편집했는데 안 했다고 판정"해 **조용한 답글 손실**을 낸다.
  가장 나쁜 실패 양상이므로 6자(24비트)를 쓴다
- 충돌 해소 수단이 필요하다 → `mrq sync --prefer md|json [--thread ID]`
- AI가 스레드 1~5를 처리하는 동안 사람이 스레드 7을 쓰는 것은 충돌이 아니다
